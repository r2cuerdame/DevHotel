# DevHotel 0.6.0

DevHotel 0.6.0 gives agents their own isolated browser per Room, runs Web Rooms on the managed runtime, wakes Rooms warm, makes runtime updates and uninstall safe, and adds two months of Room reliability fixes.

## 바뀐 점

1. 에이전트가 방마다 따로 쓰는 격리 Chromium 브라우저를 빌릴 수 있습니다. 쿠키·로그인이 방끼리 섞이지 않고 토큰 없이는 붙을 수 없으며, MCP 도구가 59개가 됐습니다. (#114)
2. 웹 방이 외부 Docker 엔진 없이 DevHotel 관리 리눅스 런타임에서 돌 수 있습니다. 런타임이 건강하지 않으면 호환 엔진으로 돌아가고, 어느 쪽으로 떴는지 알려 줍니다. 실기 부팅 검증은 아직입니다. (#107)
3. 관리 런타임이 스스로 업데이트·되돌리기·제거됩니다. 업데이트와 되돌리기에서 방 자료가 남고, 제거할 때 '앱만 제거'와 '전부 삭제'를 고릅니다. (#110)
4. 잠든 웹 방을 다시 만들지 않고 그대로 깨워 약 4초 만에 다시 응답합니다. 서비스 자료와 캐시도 남습니다. (#78)
5. 데이터베이스 복원·버전 변경이 안전해졌습니다. 앱을 잠시 멈추고, PostgreSQL 버전 낮추기는 자료를 지우기 전에 거절하며, Redis 마지막 저장이 사라지지 않습니다. (#264, #267, #269, #272, #275, #280)
6. 죽은 컨테이너를 '준비됨'으로 보이지 않고, 꺼진 방은 502 반복 대신 404 화면을 보여 줍니다. (#83, #87, #94)
7. 상태 조회·방 목록·깨우기가 Docker 호출 수 안에서 끝나 더 가볍습니다. (#70)
8. 에이전트가 잠들어 동기화가 끝난 방을 지울 수 있고, 볼륨 정리가 한 번에 정해진 시간 안에 끝납니다. (#90, #63)
9. 콘솔 닫기·방 전환·삭제·종료 때 명령, 자동화 브라우저, 연결이 남지 않고 멈추지도 않습니다. (#219, #226, #229, #231, #234, #239)
10. 나뉘어 도착한 한글 출력이 깨지거나 비밀값 가림을 빠져나가지 않습니다. 앱 시작이 실패해도 창 없이 숨은 채 남지 않습니다. (#225, #237, #253, #282)
11. 안드로이드·윈도우 방에서도 방 종류에 맞는 진단 요약을 복사할 수 있고, 기기 반납을 임대 ID로 조건부 처리합니다. (#284, #257)
12. Hyper-V 준비가 안정해졌습니다. 스크립트 인코딩, 제한 시간, 폴더 권한 거부를 안전하게 처리합니다. (#179, #187, #193)
